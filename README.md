# 핏센스 (FitSense)

내 키·몸무게와 옷의 실측 사이즈표를 비교해 **어떤 사이즈가 맞을지 추천**하는 의류 사이즈 추천 서비스의 웹 프로토타입입니다.
후기에 쓰인 체형·구매 사이즈·체감(작은 편/정사이즈/큰 편)을 모아, 나와 비슷한 체형의 후기를 근거로 보여줍니다.

## 변경 이력

> 최신 버전이 위에 있습니다. 새 버전은 이 줄 바로 아래에 추가합니다. (PRD와 아래 문서는 **최신 버전 0.4 기준**입니다.)

### 0.4 · 2026-11-16 · JSON 데이터 구조 전환, 실서비스형 화면, 추천·후기·탐색 보강
- **화면 구조**: 와이어프레임식 프레임·사이드 패널을 없애고 **모바일 우선 반응형 단일 화면**으로 정리(PC는 중앙 정렬). 모든 하위 화면에 `<` 뒤로가기와 작성 중 이탈 확인, 원형 색상 스와치 추가. **신발 카테고리 제외**(상의·하의·아우터·원피스 4종)
- **데이터 구조**: 0.3의 JSON 4종(`brands_women`·`items`·`reviews`·`user`)을 `data/brands·products·reviews.json` 3종으로 재설계(후기 작성자 정보는 reviews에 포함)하고, 불러온 직후 `checkData()`(REQUIRED / ALLOWED / TYPES / ID 참조)로 검사. 로딩 중·오류 안내와 JSON/JS 캐시 방지(`?v=빌드시각`) 추가
- **데이터 확대**: 브랜드 12 → **64**, 상품 180 → **725**(브랜드당 10~13), 후기 → **4,718**(상품당 5건 이상). 상품 성별 여성·남성·공용(여성:남성 약 8:2), 스타일 15개(시티 추가). 후기의 키·몸무게와 구매 사이즈·체감이 핏 계산식과 모순되지 않도록 생성
- **출처 표시**: 모든 항목에 `meta`(source·real·dummy·api)를 두고 화면의 출처 칩과 README 구분표를 일치시킴. 상품 이미지 경로 규칙(`asset/products/{product_id}.jpg`, `IMG_ON`) 마련
- **추천**: 계산에 **상품의 의도된 핏(오버/슬림)** 반영(오버핏은 한 치수 작은 사이즈를 권하지 않음), 기준 체형을 조정해 XS·XL 쏠림 완화
- **홈 개인화**: 홈을 "나를 위한 추천 상품 · 나를 위한 추천 브랜드 · 사이즈별 추천 브랜드" 중심으로 개편하고 "최신 후기"는 제거. 추천에 선택한 스타일과 프로필 성별을 반영하고 "스타일 일치" 근거 표시. 신체 사이즈 미입력 시 키·몸무게 미니 입력 폼 노출
- **후기**: 카드를 닉네임·날짜 → 별점 → 체형·구매·추천 사이즈 → 사이즈감 → 본문 → 키워드 → 좋아요·답글 순으로 재배치. 필터에 키 5cm·몸무게 5kg 단위(복수 선택)와 상품별 키워드(그룹별) 추가. "도움이 됐어요"는 찜/좋아요로 일원화
- **탐색**: 상품 목록·브랜드 상세 정렬에 **별점 높은순** 추가(평균 별점 → 후기 수 순, 후기 없는 상품은 맨 뒤). 브랜드 탭의 남성/여성 필터가 동작(해당 성별 상품 4개 미만 브랜드는 숨기고 "남성 상품 N개" 표시)
- **상품 링크**: 상품 개별 링크(`product_url`)를 없애고 "○○ 공식 홈페이지 가기"로 브랜드 공식 사이트에 연결
- **기록·내 옷장**: 착용 피드백을 저장하면 분석 기록이 **내 옷장 항목으로 이동**(중복 없이 갱신). 기록 보기를 3열(기본)·4열·목록으로 변경하고 이미지를 정사각형으로 축소
- **마이·알림**: 프로필 이미지·닉네임·공개용 아이디·한 줄 소개, 선호 스타일(최대 3개), 개인정보 관리(비밀번호 확인 후 진입). 비밀번호는 영문 + 특수문자 포함 8자 이상으로 강화(0.2의 4자 이상에서 변경). 알림은 날짜별로 묶고 유형(좋아요·답글·문의·찜)으로 필터. 이달의 랭킹·유저 랭킹은 제외
- **저장소 정리·배포**: `index.html · css · js · data · README` 구조로 단순화(데이터 생성·검증 도구와 별도 명세 문서는 저장소 밖으로, 명세와 출처표는 README에 통합). GitHub Pages로 배포하며 브랜드 누락 상품은 방어 처리

### 0.3 · 날짜 확인 필요 · JSON 데이터 연동과 브랜드·상품 탐색
- **데이터 구조**: 코드 안 예시 데이터를 `data/brands_women·items·reviews·user .json` 4종 + `fetch`로 분리. 브랜드 **12** · 상품 **180**(브랜드당 15) · 후기(더미). 상품은 기준 사이즈(`labeledSize`)와 실측(`measurements`)만 두고, 앱이 XS~XXL 전 사이즈 치수를 계산해 비교. 필수 JSON이 없으면 상단 오류 배너(`#data-error`)와 콘솔로 안내
- **홈**: 비로그인은 사이즈별(XS~XXL) 인기 브랜드, 로그인하면 키·몸무게가 비슷한 사용자 상위 5명(유클리드 거리)을 기준으로 맞춤 브랜드와 사이즈 추천
- **사이즈 측정 3단계**: ① 신체 사이즈(키·몸무게, 어깨·가슴·팔·허리·엉덩이·허벅지) → ② 옷 입력(브랜드·상품 검색, 옷 사진 첨부, 선호 핏) → ③ 최적 사이즈와 부위별 여유분(cm), SVG 인체 모형 시각화
- **브랜드·상품 탐색**: 브랜드 검색(예: 유니클로, 자라)과 공식 사이트 연결, 브랜드별·카테고리별 상품 목록, 상품 상세의 실측표와 체형별 후기
- **마이페이지**: 프로필(계정 관리), 내 사이즈 정보(미입력 시 키·몸무게로 자동 추정), 분석 기록, 착용 피드백(잘 맞음/큼/작음), 브랜드 좋아요
- **저장 방식**: 계정 목록 `fs_accounts`, 현재 로그인 `fs_current_user`, 계정별 신체 치수·기록·피드백·좋아요 `fs_user_<id>`(LocalStorage)
- **한계**: 상품·후기는 더미, 상품 이미지 없음(사용자 사진 첨부와 SVG 시각화로 대체), 사용자 데이터는 서버가 아니라 내 브라우저에만 저장

### 0.2 · 2026-10-28 · 로그인 추가와 단일 페이지 구조 전환
- **구조 변경**: 4개 HTML 파일(`index` / `list` / `detail` / `my`)을 `index.html` 하나로 합치고 `css/style.css` · `js/app.js`로 나눠 화면 전환을 처리. 하단 탭바는 5개에서 4개(홈 · 사이즈 측정 · 브랜드 · 마이페이지)로 줄고, 분석 결과는 사이즈 측정 흐름 안의 화면이 됨
- **로그인·회원가입 추가**: 아이디(3~24자)·비밀번호(4자 이상)만으로 가입·로그인하고 로그아웃 지원. 데이터는 계정별(`fitsense_v1_<아이디>`)로 따로 저장하고, 첫 가입 시 그 브라우저에 있던 데이터를 해당 계정으로 이전. 서버 없이 브라우저에서 동작하는 **데모 방식**
- **홈 화면**: 사이즈 측정 배너, 이용 방법 3단계(사이즈 입력 → 옷 입력 → 사이즈 판정), 내 체형 브랜드 Top 3
- **분석 방식 변경**: 핏별 범위 판정과 점수제를 없애고, 사이즈별로 **목표 여유분과의 오차 합이 가장 작은 사이즈**를 추천. 선호 핏은 정핏·여유핏·오버핏에서 **슬림·기본·여유** 3종(목표 여유 ×0.5 / ×1 / ×1.6)으로 바뀜. 사이즈 단계도 S·M·L·XL에서 카테고리별 기준(상의·아우터 XS~XXL, 하의 26~36, 원피스 XS~XL, 모자 S·M·L, 신발 220~290mm)으로 확대
- **분석 결과 화면**: 사이즈별 적합도(%) 막대 차트, 부위별 차이 표(신체 · 옷 · 차이), 기장 위치(허리 위 ~ 무릎 아래), 신뢰도(높음 ±1cm · 중간 ±2cm), 결과 화면에서 선호 핏을 바꾸면 즉시 재분석. 핏 시각화(정면·측면·3D 회전)는 **화면 틀만 남아 있음**
- **브랜드 확대**: 가상 브랜드 3개에서 **예시 브랜드 15개**로 확대하고 모자·신발 브랜드도 추가. 브랜드마다 사이즈 경향·적합도·표본 수(예시 값)와 치수 보정(−1 / 0 / +1 단계)을 반영한 추천 사이즈를 보여 주고, 저장·해제와 저장 브랜드 상세 보기 지원
- **옷 입력·사진**: 사진 유형은 착용 사진 / 사이즈표 캡처 2종(상품 이미지 유형 제거). 업로드한 사진은 긴 변 1200px, JPEG(품질 0.78)로 압축해 저장. 전신 사진은 미리보기와 삭제 지원
- **착용 피드백 확장**: 분석마다 착용 사진 첨부, 실제 입은 사이즈 · 전체 핏(작음 / 정핏 / 여유) · 부위별 착용감(가슴 · 어깨 · 소매) · 메모를 저장하고, 저장한 피드백 목록에서 수정
- **마이페이지 개편**: 탭 3개(저장한 분석 / 저장한 브랜드 / 개인정보), 요약 카드(저장 분석 수 · 완료 피드백 수 · 현재 선호 핏), 핏 프로필(키 · 가슴 · 허리 · 엉덩이 둘레)과 선호 핏 설정, **데이터 관리**(사진 / 프로필 / 분석·피드백 기록 항목별 삭제 + 로그아웃). 0.1의 사진 보관·자동 삭제 설정, 전체 삭제(확인 문구 입력), 계정 정보 화면은 이번 버전에 없음
- **데이터와 저장 방식**: 여전히 JSON 파일 없이 코드 안의 예시 데이터(브랜드 15개, 샘플 분석 기록 2건)를 사용. LocalStorage 키가 `fitsense:v1`에서 `fitsense_v1`로 바뀌어 **0.1에서 저장한 데이터는 이어지지 않음**
- **한계**: 사진은 여전히 인식하지 않고(전신 사진은 저장·표시만, 옷 사진은 첨부만), 상세 입력에서 허벅지 항목과 키·몸무게 입력 범위 검증이 빠짐. 비밀번호가 브라우저에 **평문**으로 저장됨. 브랜드 수치는 가상의 예시 값

### 0.1 · 2026-10-13 · 초기 프로토타입
- **서비스 정의**: 사진과 키·몸무게로 신체 사이즈를 정하고, 옷의 사이즈 정보를 입력하면 **사이즈별 적합도와 추천 사이즈**를 보여 주는 흐름을 처음 구현
- **화면 4개 + 하단 탭바 5개**(홈 · 사이즈 입력 · 분석 결과 · 브랜드 · 마이): `index.html`(홈·사이즈 입력) / `list.html`(분석 결과·브랜드 목록) / `detail.html`(브랜드 상세·저장 분석 상세·저장 브랜드) / `my.html`(마이)
- **신체 사이즈 입력**: 전신 사진 + 키·몸무게(키 130~210cm, 몸무게 30~200kg 검증). 직접 아는 항목만 넣는 **상세 입력**(어깨너비·팔길이·가슴·허리·힙·다리 안쪽·허벅지)과 측정 위치 안내
- **옷 입력**: 카테고리 6종(상의·하의·원피스·아우터·모자·신발), 사진·캡처 여러 장(착용 사진 / 사이즈표 캡처 / 상품 이미지), 사이즈 라벨(S·M·L·XL·프리·직접 입력), 상세 실측(선택)
- **분석 결과**: 추천 사이즈, 사이즈별 점수, **부위별 차이 표**(신체 · 옷 · 차이 · 판정), 핏 시각화(정면·측면), 신뢰도(높음·중간·낮음)와 오차 범위, 선호 핏(정핏·여유핏·오버핏) 변경 후 재분석. 3D 회전은 "준비 중"
- **브랜드 추천**: 내 체형에 맞는 브랜드 순위와 브랜드 상세(사이즈 경향·신체 기준 평균 차이), 이 브랜드 옷 바로 분석하기, 브랜드 저장(내 옷장)
- **저장·기록**: 분석 결과 저장, 저장한 분석 다시 보기·삭제, **착용 피드백**(실제 입은 사이즈·메모) 남기기
- **마이페이지**: 계정 정보, 사진 보관/자동 삭제 설정, 삭제 범위 선택(사진만 / 신체 프로필 / 기록·피드백 / 전체 — 전체 삭제는 확인 문구 입력)
- **데이터와 저장 방식**: JSON 파일 없이 코드 안의 예시 데이터를 사용하고, 사용자가 입력한 값은 브라우저 LocalStorage(`fitsense:v1`)에 저장
- **한계**: 사진은 인식하지 않고(전신 사진은 세로 비율만 확인, 옷 사진은 첨부만) 입력값이나 예시 값으로 분석, 브랜드는 가상의 "브랜드 A·B·C" 3개

## PRD (제품 요구사항)

> 최신 버전(0.4) 기준입니다. 버전별 변화는 위의 **변경 이력**을 확인하세요.

### 1. 배경과 문제
- 온라인으로 옷을 살 때 사이즈 선택이 가장 큰 불확실성입니다. 같은 M이라도 브랜드마다 실제 치수가 다르고, 사이즈표는 상품 이미지에 흩어져 있어 읽기 어렵습니다.
- 후기는 많지만 "나와 비슷한 체형의 사람이 어떤 사이즈를 샀는지"를 찾기 어렵습니다. 키·몸무게가 적혀 있어도 직접 걸러 봐야 합니다.
- 잘못 고른 사이즈는 교환·반품으로 이어져 사용자에게는 번거로움, 브랜드에는 비용입니다.

### 2. 목표
| 구분 | 내용 |
|---|---|
| 사용자 목표 | 키·몸무게만 입력해도 상품마다 **내게 맞을 사이즈와 그 근거**를 바로 본다 |
| 서비스 목표 | 측정 → 추천 → 후기 확인 → 구매(브랜드 공식 사이트) 흐름을 한 서비스 안에서 끝낸다 |
| 비즈니스 목표 | 사이즈 고민이 큰 구매 직전 사용자를 모아 브랜드 연결(공식 사이트 이동)로 수익화한다 (가설) |
| 학습 목표(수업) | JSON 데이터 설계 → fetch → 검색·필터·정렬·state → 출처 표기까지 실제 브라우저에서 동작 |

| 구매 연결률 | 추천 사이즈 확인 후 브랜드 공식 사이트로 이동한 비율 |

### 3. 타깃 사용자 (가설)
| 페르소나 | 상황 | 핵심 니즈 |
|---|---|---|
| 20대 여성, 온라인 쇼핑 잦음 | 브랜드마다 사이즈가 달라 매번 후기를 뒤짐 | 내 체형 기준 사이즈 한 줄 답, 반품 줄이기 |
| 20~30대 남성, 공용(유니섹스) 상품 위주 | 여성 모델 기준 사이즈표가 헷갈림 | 공용 상품의 남성 기준 추천, 오버핏 의도 반영 |

### 4. 핵심 사용자 흐름
1. 홈에서 키·몸무게를 입력하면 "내 사이즈 카드"와 **나를 위한 추천 상품·브랜드**가 열린다.
2. 상품 상세에서 **사이즈표와 부위별 판정**(타이트/적당/여유), 추천 사이즈를 본다.
3. **나와 비슷한 체형의 후기**만 걸러 보고, 키·몸무게·키워드로 더 좁힌다.
4. 맞는 사이즈를 정하면 **브랜드 공식 홈페이지**로 이동해 구매한다.
5. 입어본 뒤 **착용 피드백**을 남기면 내 옷장에 쌓이고, 이후 추천이 정교해진다.

### 6. 추천 알고리즘 요약
- **신체 추정**: 키·몸무게로 어깨·가슴·허리·힙·허벅지·소매 둘레를 추정합니다(예: 가슴 ≈ 키×0.5 + (몸무게−52)×0.6 + 2). 직접 입력한 실측이 있으면 그 값을 씁니다.
- **목표 여유분**: 카테고리별로 몸 치수에 더할 여유(cm)를 둡니다. 예) 상의 가슴 +14, 아우터 가슴 +22, 하의 허리 +4·힙 +7, 원피스 허리 +14.
- **보정**: 선호 핏(슬림 −1 / 여유 +1.2 단위), 신축성, **상품의 의도된 핏**(오버핏은 크게 입는 옷이라 한 치수 작은 사이즈를 권하지 않음), 내 옷장 피드백(마이핏드백)을 더합니다.
- **판정**: 부위별 오차가 허용 범위(예: 가슴 4.5cm, 어깨 1.6cm) 안이면 "적당", 작으면 "타이트", 크면 "여유". 부위 가중치(상의: 가슴 0.75·어깨 0.25 등)로 점수를 합쳐 가장 낮은 사이즈를 추천합니다.
- **근거 제시**: 같은 체형(키 ±6~8cm, 몸무게 ±7~10kg) 후기의 사이즈·체감 비율을 함께 보여 줍니다.
- **스타일·성별**: 홈 추천은 프로필 성별에 맞는 상품만, 선택한 스타일과 브랜드 스타일이 겹칠수록 가중합니다.

### 7. 비즈니스 · CS 관점 (가설)
- **수익화**: 브랜드 공식 사이트 이동 성과 기반 제휴(CPA/CPC), 브랜드 사이즈 데이터 리포트. 공식 사이트로 연결하므로 상품 개별 링크는 두지 않습니다.
- **신뢰**: 더미/실제를 화면과 README에 항상 구분 표기하고, 후기·사이즈표의 출처를 meta로 남깁니다.
- **CS**: 사이즈표 오류·정보 오류 신고와 브랜드·상품 추가 요청을 앱 안 문의로 받고, 답변 상태를 알림으로 알립니다.
- **데이터 선순환**: 착용 피드백이 쌓일수록 추천이 정교해지고, 공개 동의한 피드백은 다른 사용자의 후기가 되도록 설계했습니다.

### 8. 심화 트랙 계획
- 필수 트랙(JSON + fetch + 필터·정렬 + 출처 표기)을 먼저 완성하고 GitHub Pages로 배포합니다.
- 클라우드 DB(Supabase 또는 Firebase)는 **사용자가 만드는 공유 데이터**(후기·좋아요·답글·문의)와 간단한 로그인에만 적용합니다.
- 브랜드·상품 카탈로그는 JSON을 그대로 쓰고, DB 연결이 실패하면 JSON/LocalStorage로 동작하는 **대체 경로(fallback)**를 둡니다.
- 외부 API는 현재 서비스에 필요한 부분이 없어 쓰지 않습니다.
