# 핏센스 (FitSense)

내 키·몸무게와 옷의 실측 사이즈표를 비교해 **어떤 사이즈가 맞을지 추천**하는 의류 사이즈 추천 서비스의 웹 프로토타입입니다.
후기에 쓰인 체형·구매 사이즈·체감(작은 편/정사이즈/큰 편)을 모아, 나와 비슷한 체형의 후기를 근거로 보여줍니다.

## 변경 이력

> 최신 버전이 위에 있습니다. 새 버전은 이 줄 바로 아래에 추가합니다. (PRD와 아래 문서는 **최신 버전 0.6 기준**입니다.)

### fs0.5 (종합본) · 2026-11-22 · 0.6 이후 수정사항 종합, 찜 개편, 화면 전환·반응 효과

이 폴더는 이전 0.5가 아니라 0.6 이후 수정사항을 모두 합친 최신본이에요.

- **찜**: 상품 · 후기 · 브랜드 · 폴더 4탭(탭마다 개수). 탭마다 조건 알약(내 사이즈·종류·가격 / 체형·판정·종류 / 사이즈 경향·종류 / 체형·종류)을 누르면 선택 시트가 열리고, 고르면 알약이 검게 바뀌며 값이 붙음. 결과 개수와 정렬 전환, 빈 상태 안내 버튼. 브랜드 줄에는 내 사이즈 맞는 옷 개수와 사이즈 경향. 오른쪽 위 "최근 본" 링크 제거(마이 메뉴에 있음).
- **화면 전환**: 다음 화면은 오른쪽에서, 뒤로 가면 왼쪽에서 밀려 들어옴. 하단 탭 이동은 살짝 떠오름.
- **시트**: 열릴 때 살짝 튕기며 올라오고, 닫힐 때 내려가며 사라짐. 같은 시트 안에서 선택만 바뀔 때는 다시 튕기지 않음.
- **저장·오류 반응**: 저장·완료 안내에는 체크 표시가 그려짐. 입력이 빠진 안내는 방금 누른 버튼이 좌우로 흔들림. 옷 입력에서는 비어 있는 칸이 빨갛게 표시되며 흔들림. 안내는 화면 위쪽에 떠서 버튼을 가리지 않음.
- 기기 설정이 "움직임 줄이기"면 모든 효과가 꺼짐.

### 0.6.1 · 2026-11-22 · 브랜드 상세 정리, 기록 검색, 옷 입력 개편, 폴더 필터

- **브랜드 상세**: 중복되던 사이즈 경향 버튼·탭·카드를 없애고 정보 한 줄(상품 · 후기 · 경향)로 합침. 공식 사이트는 브랜드 이름 옆 작은 링크. 탭은 상품/후기.
- **기록 검색**: 글자를 입력하면 관련 종류·브랜드·상품명·사이즈·입어보니·폴더·기간이 아래에 나오고, 고르면 칩으로 쌓임. 필터 시트와 카테고리 칩 줄은 제거.
- **옷 입력**: 옷 정보 / 착용감 두 카드. 브랜드·상품명 자동완성(목록에 없으면 "'○○' 그대로 입력"), 색상은 21색 견본, 부위별 착용감, 빠른 메모 태그 + 여러 줄 메모.
- **색상 통일**: 상품 필터·상품 상세·옷 입력·기록이 같은 21색(`COLOR_HEX`, 순서 `COLOR_ORD`)을 씀.
- **폴더 전체**: 2열 카드에 "나에게 맞는 옷 n/m", 검색, 종류 칩, 정렬. 필터 시트에는 키·몸무게 범위 슬라이더(분포 막대, ±3·±5·±10·전체), 옷 종류, 사이즈 고민(후기의 부위별 평가로 계산), 분위기, 나에게 맞는 옷. 새 폴더 만들 때 분위기 선택(선택 사항).
- **알림**: 제목 아래 필터 칩(전체·답글·좋아요·기타, 안 읽으면 점)과 날짜별 목록. 답글은 썸네일·인용 박스·"답글 달기" 버튼이 있는 행, 좋아요·찜·문의는 아이콘 한 줄. 안 읽은 알림은 연노랑 배경.
- **마이**: 후기·답글·폴더 숫자 3칸을 없애고 메뉴만 남김. "내 후기"는 후기만 모아 보여줌(상품·산 사이즈·판정·메모). "최근 본 상품"은 3열 카드, "비우기"는 한 줄.
- **정리**: 화면에 보이던 "프로토타입이라 …" 안내 문구와 "(프로토타입)" 버튼 이름을 제거.

### 0.6 · 2026-11-22 · 파스텔 카드 UI, 폴더(내 옷장 플레이리스트), 옷 추가 3단계, 효과

- **디자인**: 흰 바탕에 노랑·하늘·회색 카드, 얇고 큰 문장 제목, 검정 원형·알약 버튼. 영문 라벨과 전용 용어는 쓰지 않음.
- **폴더**: 내 옷장에서 폴더를 만들고(이름·소개·카드 색·공개) 옷 담기·순서 바꾸기·빼기·공개 전환. 홈에는 비슷한 체형의 폴더, 폴더 상세에는 "나와 비교"와 옷별 "나는 M 맞아요"가 보임. 다른 사람의 폴더는 후기 작성자 데이터로 만든 더미.
- **옷 추가**: 상품 DB 검색 → 산 사이즈 → 작아요/맞아요/커요 3단계. 찾는 옷이 없으면 직접 입력(기존 폼).
- **마이**: 프로필, 내 몸 카드, 후기·답글·폴더 숫자, 메뉴 4줄. 설정은 한 화면으로 묶음.
- **효과**: 누르면 눌림, 하트 튀김, 화면 등장, 숫자 올라가기, 강조 밑줄. 기기 설정이 "움직임 줄이기"면 모두 꺼짐.
- **홈**: 상단 문장 삭제. 로그인·프로필(선호 스타일) 완성 시 "나를 위한 추천 상품·브랜드" 생성(전체 보기 페이지 포함). 폴더·사이즈 토크 "전체" 페이지에 필터·정렬 추가.
- **내 옷장과 비교**: 측정 결과와 상품 사이즈 탭에서 옷장 옷을 골라 부위별 치수 차이를 비교.
- **필터 보강**: 상품 필터에서 브랜드 삭제, 가격대·"내 사이즈에 맞는 옷만" 추가. 기록은 검색·사이즈·입어본 느낌·브랜드·폴더·공개·기간 필터와 정렬(최신·오래된·브랜드) 추가.
- **기록·마이**: 폴더 색 7종, 기본 프로필은 사람 모양, 내 후기·답글은 로그인해야 보임, 옷 직접 입력은 브랜드를 꼭 고르지 않아도 됨.
- 새 파일: `js/v06.js`, `css/v06.css` (0.5의 기존 파일 위에 덮어쓰는 방식이라 0.5와 비교하기 쉬움).

- **탐색**: 상품 목록·브랜드 상세 정렬에 **별점 높은순** 추가(평균 별점 → 후기 수 순, 후기 없는 상품은 맨 뒤). 브랜드 탭의 남성/여성 필터가 동작(해당 성별 상품 4개 미만 브랜드는 숨기고 "남성 상품 N개" 표시)
- **상품 링크**: 상품 개별 링크(`product_url`)를 없애고 "○○ 공식 홈페이지 가기"로 브랜드 공식 사이트에 연결
- **기록·내 옷장**: 착용 피드백을 저장하면 분석 기록이 **내 옷장 항목으로 이동**(중복 없이 갱신). 기록 보기를 3열(기본)·4열·목록으로 변경하고 이미지를 정사각형으로 축소
- **마이·알림**: 프로필 이미지·닉네임·공개용 아이디·한 줄 소개, 선호 스타일(최대 3개), 개인정보 관리(비밀번호 확인 후 진입). 비밀번호는 영문 + 특수문자 포함 8자 이상으로 강화(0.2의 4자 이상에서 변경). 알림은 날짜별로 묶고 유형(좋아요·답글·문의·찜)으로 필터. 이달의 랭킹·유저 랭킹은 제외
- **저장소 정리·배포**: `index.html · css · js · data · README` 구조로 단순화(데이터 생성·검증 도구와 별도 명세 문서는 저장소 밖으로, 명세와 출처표는 README에 통합). GitHub Pages로 배포하며 브랜드 누락 상품은 방어 처리

### 0.3 · 날짜 확인 필요 · JSON 데이터 연동과 브랜드·상품 탐색
- **데이터 구조**: 코드 안 예시 데이터를 `data/brands_women·items·reviews·user .json` 4종 + `fetch`로 분리. 브랜드 **12** · 상품 **180**(브랜드당 15) · 후기(더미). 상품은 기준 사이즈(`labeledSize`)와 실측(`measurements`)만 두고, 앱이 XS~XXL 전 사이즈 치수를 계산해 비교. 필수 JSON이 없으면 상단 오류 배너(`#data-error`)와 콘솔로 안내
- **홈**: 비로그인은 사이즈별(XS~XXL) 인기 브랜드, 로그인하면 키·몸무게가 비슷한 사용자 상위 5명(유클리드 거리)을 기준으로 맞춤 브랜드와 사이즈 추천
- **사이즈 측정 3단계**: ① 신체 사이즈(키·몸무게, 어깨·가슴·팔·허리·엉덩이·허벅지) → ② 옷 입력(브랜드·상품 검색, 옷 사진 첨부, 선호 핏) → ③ 최적 사이즈와 부위별 여유분(cm), SVG 인체 모형 시각화
- **브랜드·상품 탐색**: 브랜드 검색(예: 유니클로, 자라)과 공식 사이트 연결, 브랜드별·카테고리별 상품 목록, 상품 상세의 실측표와 체형별 후기

### 1. 배경과 문제
- 온라인으로 옷을 살 때 사이즈 선택이 가장 큰 불확실성입니다. 같은 M이라도 브랜드마다 실제 치수가 다르고, 사이즈표는 상품 이미지에 흩어져 있어 읽기 어렵습니다.

### 6. 추천 알고리즘 요약
- **신체 추정**: 키·몸무게로 어깨·가슴·허리·힙·허벅지·소매 둘레를 추정합니다(예: 가슴 ≈ 키×0.5 + (몸무게−52)×0.6 + 2). 직접 입력한 실측이 있으면 그 값을 씁니다.
- **목표 여유분**: 카테고리별로 몸 치수에 더할 여유(cm)를 둡니다. 예) 상의 가슴 +14, 아우터 가슴 +22, 하의 허리 +4·힙 +7, 원피스 허리 +14.
- **보정**: 선호 핏(슬림 −1 / 여유 +1.2 단위), 신축성, **상품의 의도된 핏**(오버핏은 크게 입는 옷이라 한 치수 작은 사이즈를 권하지 않음), 내 옷장 피드백(마이핏드백)을 더합니다.
- **판정**: 부위별 오차가 허용 범위(예: 가슴 4.5cm, 어깨 1.6cm) 안이면 "적당", 작으면 "타이트", 크면 "여유". 부위 가중치(상의: 가슴 0.75·어깨 0.25 등)로 점수를 합쳐 가장 낮은 사이즈를 추천합니다.
- **근거 제시**: 같은 체형(키 ±6~8cm, 몸무게 ±7~10kg) 후기의 사이즈·체감 비율을 함께 보여 줍니다.
- **스타일·성별**: 홈 추천은 프로필 성별에 맞는 상품만, 선택한 스타일과 브랜드 스타일이 겹칠수록 가중합니다.

### 8. 심화 트랙 계획
- 필수 트랙(JSON + fetch + 필터·정렬 + 출처 표기)을 먼저 완성하고 GitHub Pages로 배포합니다.
- 클라우드 DB(Supabase 또는 Firebase)는 **사용자가 만드는 공유 데이터**(후기·좋아요·답글·문의)와 간단한 로그인에만 적용합니다.

- 외부 API는 현재 서비스에 필요한 부분이 없어 쓰지 않습니다.

## 사진 분석(AI) 연결 — js/api.js · js/config.js · tools/worker.js
사이즈표 사진을 올리고 숫자를 따로 입력하지 않으면 AI가 사진에서 사이즈별 실측을 읽어요.
- 결과는 알려진 사이즈(XS~XL)와 부위, 5~220cm 범위의 숫자만 받아요. 이상한 값은 버려요.
- **실패해도 분석은 끝까지 가요.** 오프라인, 25초 초과, 한도 초과(429), 읽기 실패, 서버 오류 때는 이유를 안내하고 예시 사이즈표로 분석해요. 직접 입력과 등록 상품 불러오기는 AI와 상관없이 항상 돼요.
- `js/config.js`의 `aiEndpoint`가 비어 있으면 AI를 쓰지 않고 예전 방식으로 동작해요.
- 키는 GitHub에 올리지 않아요. `tools/worker.js`를 Cloudflare Worker로 배포하고 Gemini 키는 Worker의 Secret(`GEMINI_API_KEY`)에만 넣어요.

- 첫 화면이 열리는 동안 스켈레톤을 보여주고, 데이터를 못 불러오면 "다시 시도" 화면이 나와요.
- 인터넷이 끊기면 위에 "오프라인이에요" 안내가 뜨고, 다시 연결되면 사라져요.
- 로그인이 필요한 동작(답글·댓글·알림)은 로그인 안내 시트가 나와요.

## LocalStorage 저장 규칙 (js/store.js)
이 브라우저에서만 쓰는 개인 상태만 저장해요. 캐시·사이트 데이터를 지우면 사라져요. 모든 키 앞에 `fitsense-`를 붙여요.

| 키 | 형식 | 기본값 | 보이는 곳 |
|---|---|---|---|
| `fitsense-favorites` | `{product:[id], brand:[id], review:[id], folder:[id]}` | 전부 `[]` | 찜 화면·하트 |
| `fitsense-recent` | 상품 id 배열(최근 순, 최대 10개) | `[]` | 최근 본 상품 |
| `fitsense-filters` | `{plist:{…}, folders:{…}}` | `{}` | 상품·폴더 목록 조건 |
| `fitsense-ui` | `{tutorialHide, nset}` | 앱 기본값 | 튜토리얼 다시 안 보기·알림 설정 |
| `fitsense-body` | `{h, w, pref, updated}` (키·몸무게·선호 핏) | 없음 | 홈·추천·사이즈 판정 |

- **저장하지 않는 것**: 이름·사진·로그인/비밀번호·후기·댓글·폴더 내용·옷장·문의. (키·몸무게는 서비스에 꼭 필요해 이 브라우저에만 저장해요. 숫자 범위가 이상하면 버려요.) 새로고침하면 사라지고, 서버 DB(Supabase) 연결 후 DB에 저장해요.
- 저장값이 없거나 손상되면 기본값으로 복구하고, 없는 ID는 화면을 그릴 때 정리해요.
- 옛 버전의 통째 저장 키(`fitsense_wf_v5`)는 찜·최근 본만 새 키로 옮기고 삭제해요.
- DB 표 설계와 접근 규칙(RLS)은 `tools/supabase.sql`.

## 브랜드 선택
브랜드 검색 목록 맨 위에 항상 **(직접 입력)** 이 있어요. 우리 DB에 없는 브랜드나 사이트도 선택할 수 있고, 글자를 입력하면 `입력한 글자 (직접 입력)`으로 보여요.

## 이번 수정 (로그인·프로필·문구)
- 프로필은 로그인해야 열려요. 로그아웃 상태에서 누르면 로그인 안내가 떠요(주소로 직접 들어와도 막아요).
- 로그인·회원가입 화면: 입력칸 바로 아래에 오류 안내, 비밀번호 표시/숨기기, 가입 시 비밀번호 조건 실시간 체크, Enter로 제출. 로그인 실패 문구는 "이메일 또는 비밀번호를 확인해 주세요" 하나로 통일했어요.
- 사이즈 문구의 조사를 받침에 맞게 고쳤어요(예: "어깨가 커요", "가슴이 작아요", "허리가 커요").
- "체험용 비밀번호" 안내 문구를 없앴어요.
